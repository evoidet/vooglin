# Vooglin

Minimal website for Vooglin automation and digital workflow services.

## Preview locally

```bash
python3 -m http.server 8000
```

Open `http://localhost:8000`. The pricing and privacy pages are available at `http://localhost:8000/pricing/` and `http://localhost:8000/privacy/`.

## Build

```bash
npm run build
```

The build packages all pages, search metadata, brand assets, the social preview image and the booking-request API into a deployment-ready Sites Worker, and writes the static `public/` output used by Vercel.

The plain Python preview serves static files only. It can display and validate the booking form, but successful delivery requires either the built Sites Worker or the Vercel Function in `api/booking.js`, with the booking environment values below configured in the deployment target that serves the site.

## Edit the content

- Homepage structure and public copy are in `index.html`.
- Pricing structure and copy are in `pricing/index.html`.
- Privacy Policy structure and English source copy are in `privacy/index.html`; Estonian and Russian versions are generated by `localize.mjs`.
- Visual styling and responsive layouts are in `styles.css`.
- The current year, mobile navigation, booking dialog, calculator, counters, verified-client motion, split-scroll story, reveal effects and reusable Canvas backgrounds are handled in `script.js`.
- Verified statistics, client entries and public booking preferences are maintained in `site-config.js`.
- Put future verified client logos in `images/partners/`, then reference them as `/images/partners/filename.svg` in `site-config.js`.
- Put only explicitly approved future client portraits in `images/people/`, then add an `approved: true` entry to `people` in `site-config.js`; the photo strip stays hidden while that list is empty.
- `egor.png` is the retained original founder photo; the website serves the optimized `egor-portrait.webp` derivative rendered by `scripts/render-portrait-asset.mjs`.
- `vooglin-v-black.png` is the compact black-and-white V used in headers and footers. `scripts/render-simple-v-assets.mjs` renders its favicon, Apple Touch Icon and Organization-logo variants.
- `vooglin-mark.png` is the retained detailed transparent mark used only as the large decorative hero watermark. Previous logo and favicon source files remain in the repository.
- `robots.txt`, `sitemap.xml` and `site.webmanifest` are copied and served by the deployment build.
- `og-brand.png` is the current social preview card; it stays separate from favicon and Organization-logo metadata.

## Booking request delivery

The form submits to `POST /api/booking`. It creates a meeting request, not a confirmed calendar booking. The endpoint is included in the generated Sites Worker and in `api/booking.js` for Vercel. Both report success only after an owner-controlled HTTPS webhook accepts the request.

Configure these runtime values in the hosting environment that actually serves the site (Sites or Vercel):

- `BOOKING_WEBHOOK_URL` — required HTTPS webhook that delivers the request to the owner.
- `BOOKING_WEBHOOK_TOKEN` — optional bearer token for that webhook.
- `BOOKING_RECIPIENT_EMAIL` — optional recipient override; defaults to `egor@vooglin.ee`.

The webhook receives plain JSON containing the contact details, requested Tallinn date/time, configured meeting duration, automation description, locale and source page. It can send the owner notification and, if desired, a visitor confirmation email. When delivery is not configured or fails, the website shows a prefilled email fallback instead of a false success message.

The endpoint validates the configured date range and preferred times, requires a same-origin form submission, limits request size, and uses a honeypot plus form-timing checks. For higher traffic, add a host-level rate limit in Sites/Vercel or in the receiving webhook; the project has no durable rate-limit store today.
